# 2026-09-04 작업 로그

## 1. 연습 파트 "이어서 연습하기" — 로딩 표시 + 빈 상태 안내

## 요청 사항

"연습 모드 등에서 내 번호를 저장한 상태면 연습모드 처음 창에서 맨 위에 이어서
하기를 할 수 있는데, 이전의 연습 데이터베이스를 불러올 때 시간이 좀 걸리고
갑자기 뜨니까, 번호가 지정되어 있을 때는 데이터베이스를 불러올 때 로딩 이미지와
애니메이션을 아무거나 넣어줘 내가 맞게 수정할게, 그리고 로딩 후 이전처럼
데이터베이스를 나타내거나 데이터베이스에 저장된 데이터가 없으면 '저장된 데이터가
없습니다.'를 파란색 박스에 이전과 같이 출력해줘. 클릭은 안되는 박스로"

## 원인

`practice/page.tsx`의 "이어서 연습하기" 목록(파일 선택 화면 맨 위, 저장된 진행이
있는 파일 조합들을 카드로 보여주는 부분)은 `listSavedProgress()`가 서버(Supabase)
+ 로컬 사본을 병합해 돌려주는 동안 `savedList`가 빈 배열(`[]`)인 채로 렌더되다가,
응답이 오면 갑자기 카드가 나타났다. 로딩 중인지 "정말 저장된 게 없는지"를 화면에서
구분할 수 없어서, 느린 네트워크에서는 "잠깐 아무것도 없다가 갑자기 뜨는" 것처럼
보였다.

## 수정

- `savedListLoading` state를 추가해, `listSavedProgress()`를 부르기 직전에
  `true`로 켜고 응답이 오면(`.then()` 안에서) `false`로 끈다.
- 로딩 중(`ready && userId && savedListLoading`)에는 Spinner + 펄스
  애니메이션(`animate-pulse`)이 있는 스켈레톤 카드를 보여준다 — 사용자가 "아무거나
  넣어달라, 내가 맞게 수정하겠다"고 해서 최소한의 자리표시자로 구성했다(나중에
  원하는 이미지/애니메이션으로 바꾸기 쉽도록 이 블록만 통째로 교체하면 됨).
- 로딩이 끝났고 저장된 항목이 있으면(`!savedListLoading && savedList.length > 0`)
  기존과 동일한 카드 목록을 그대로 보여준다(로직 변경 없음).
- 로딩이 끝났는데 저장된 항목이 하나도 없으면(`ready && userId &&
  !savedListLoading && savedList.length === 0`) "저장된 데이터가 없습니다."를
  파란색 텍스트/테두리 박스(`var(--blue)`)로 보여준다. `<button>`/`<Link>`가 아닌
  일반 `<div>`라 클릭해도 아무 반응이 없다(요청대로 "클릭은 안되는 박스").
  (참고: 이 정확한 문구/박스가 과거 git 이력에는 없어서 "이전과 같이"는 아마 다른
  화면의 안내 박스 스타일을 뜻하는 것으로 보고, 기존 초록색 안내 박스와 같은
  구조(둥근 모서리·굵은 글씨·테두리)에 색만 파란색 계열로 만들었다.)

## 검증

`tsc --noEmit`·`eslint src/` 통과. 로컬 dev 서버(Supabase 미설정 환경)에서 크롬으로:

- 번호를 저장한 상태에서 `/practice`를 열어, 저장된 진행이 없을 때 "저장된 데이터가
  없습니다." 파란 박스가 정확한 문구로 뜨는 것을 확대 캡처로 확인.
- 연습을 시작해 한 단어를 채점한 뒤 "연습 종료하기"로 나가고 페이지를 새로고침해,
  "이어서 연습하기 (1개)" 카드가 다시 정상적으로 뜨는 것도 확인(로직이 안 깨졌음을
  같이 검증).
- 로컬 환경(Supabase 미설정)에서는 `listSavedProgress`가 로컬 저장소만 읽어
  거의 즉시 끝나기 때문에 로딩 스켈레톤이 화면에 오래 머무는 걸 실제로 붙잡아
  캡처하지는 못했다 — 코드 경로(로딩 시작 → 응답 후 종료)는 확인했지만, 실제
  네트워크 지연이 있는 배포 환경에서 스켈레톤이 잠깐 보였다가 사라지는 것까지는
  이번 검증 범위 밖이다.
- 확인 중 만든 테스트 진행 데이터와, 이 브라우저 프로필에 예전부터 남아있던 테스트
  번호("999999test")까지 전부 `localStorage`에서 지워서 원래 상태로 돌려놨다.

## 기존 학습 DB에 미치는 영향: 없음

로딩 상태를 보여줄지 말지를 결정하는 프론트엔드 표시 로직만 추가했다.
`listSavedProgress`가 실제로 무엇을 언제 불러오는지, 그 결과로 무엇을 저장하는지는
전혀 바꾸지 않았다.
