# 2026-09-04 작업 로그

## 1. 연습 파트 "이어서 연습하기" — 로딩 표시 + 빈 상태 안내

## 요청 사항

"연습 모드 등에서 내 번호를 저장한 상태면 연습모드 처음 창에서 맨 위에 이어서
하기를 할 수 있는데, 이전의 연습 데이터베이스를 불러올 때 시간이 좀 걸리고
갑자기 뜨니까, 번호가 지정되어 있을 때는 데이터베이스를 불러올 때 로딩 이미지와
애니메이션을 아무거나 넣어줘 내가 맞게 수정할게, 그리고 로딩 후 이전처럼
데이터베이스를 나타내거나 데이터베이스에 저장된 데이터가 없으면 '저장된 데이터가
없습니다.'를 파란색 박스에 이전과 같이 출력해줘. 클릭은 안되는 박스로"

## 원인

`practice/page.tsx`의 "이어서 연습하기" 목록(파일 선택 화면 맨 위, 저장된 진행이
있는 파일 조합들을 카드로 보여주는 부분)은 `listSavedProgress()`가 서버(Supabase)
+ 로컬 사본을 병합해 돌려주는 동안 `savedList`가 빈 배열(`[]`)인 채로 렌더되다가,
응답이 오면 갑자기 카드가 나타났다. 로딩 중인지 "정말 저장된 게 없는지"를 화면에서
구분할 수 없어서, 느린 네트워크에서는 "잠깐 아무것도 없다가 갑자기 뜨는" 것처럼
보였다.

## 수정

- `savedListLoading` state를 추가해, `listSavedProgress()`를 부르기 직전에
  `true`로 켜고 응답이 오면(`.then()` 안에서) `false`로 끈다.
- 로딩 중(`ready && userId && savedListLoading`)에는 Spinner + 펄스
  애니메이션(`animate-pulse`)이 있는 스켈레톤 카드를 보여준다 — 사용자가 "아무거나
  넣어달라, 내가 맞게 수정하겠다"고 해서 최소한의 자리표시자로 구성했다(나중에
  원하는 이미지/애니메이션으로 바꾸기 쉽도록 이 블록만 통째로 교체하면 됨).
- 로딩이 끝났고 저장된 항목이 있으면(`!savedListLoading && savedList.length > 0`)
  기존과 동일한 카드 목록을 그대로 보여준다(로직 변경 없음).
- 로딩이 끝났는데 저장된 항목이 하나도 없으면(`ready && userId &&
  !savedListLoading && savedList.length === 0`) "저장된 데이터가 없습니다."를
  파란색 텍스트/테두리 박스(`var(--blue)`)로 보여준다. `<button>`/`<Link>`가 아닌
  일반 `<div>`라 클릭해도 아무 반응이 없다(요청대로 "클릭은 안되는 박스").
  (참고: 이 정확한 문구/박스가 과거 git 이력에는 없어서 "이전과 같이"는 아마 다른
  화면의 안내 박스 스타일을 뜻하는 것으로 보고, 기존 초록색 안내 박스와 같은
  구조(둥근 모서리·굵은 글씨·테두리)에 색만 파란색 계열로 만들었다.)

## 검증

`tsc --noEmit`·`eslint src/` 통과. 로컬 dev 서버(Supabase 미설정 환경)에서 크롬으로:

- 번호를 저장한 상태에서 `/practice`를 열어, 저장된 진행이 없을 때 "저장된 데이터가
  없습니다." 파란 박스가 정확한 문구로 뜨는 것을 확대 캡처로 확인.
- 연습을 시작해 한 단어를 채점한 뒤 "연습 종료하기"로 나가고 페이지를 새로고침해,
  "이어서 연습하기 (1개)" 카드가 다시 정상적으로 뜨는 것도 확인(로직이 안 깨졌음을
  같이 검증).
- 로컬 환경(Supabase 미설정)에서는 `listSavedProgress`가 로컬 저장소만 읽어
  거의 즉시 끝나기 때문에 로딩 스켈레톤이 화면에 오래 머무는 걸 실제로 붙잡아
  캡처하지는 못했다 — 코드 경로(로딩 시작 → 응답 후 종료)는 확인했지만, 실제
  네트워크 지연이 있는 배포 환경에서 스켈레톤이 잠깐 보였다가 사라지는 것까지는
  이번 검증 범위 밖이다.
- 확인 중 만든 테스트 진행 데이터와, 이 브라우저 프로필에 예전부터 남아있던 테스트
  번호("999999test")까지 전부 `localStorage`에서 지워서 원래 상태로 돌려놨다.

## 기존 학습 DB에 미치는 영향: 없음

로딩 상태를 보여줄지 말지를 결정하는 프론트엔드 표시 로직만 추가했다.
`listSavedProgress`가 실제로 무엇을 언제 불러오는지, 그 결과로 무엇을 저장하는지는
전혀 바꾸지 않았다.

## 2. 한자 힌트 크기만 바로 조절하는 기능 — 연습 화면 ⚙ 설정 + 메인 설정

## 요청 사항

"연습 모드 등에서 한자 크기만 잘보이게 하는 기능을 연습모드 안에 설정버튼에 넣고,
가장 메인 설정에도 한자 크기만 조절 할 수 있는 기능을 넣어줘. 한자 부수가 많아지면
휴대폰 같은 작은 화면에서 안보여서 그래."

이미 "글자 크기 설정" 페이지에 힌트 구간별(읽기/한자 분해/종합/치트키/…) 색·크기를
전부 조절하는 패널이 있지만, 부수 분해가 길어져서 안 보이는 문제 하나만 급하게
고치려고 매번 그 페이지까지 가는 게 번거롭다는 취지로 이해했다 — "한자 크기"라는
단일 값 하나만 두 군데(연습 화면 안, 메인 설정)에서 바로 조절할 수 있게 지름길을
만들었다.

## 구현

`hintTheme.ts`의 `kanji` 구간(음독/훈독/분해/어원/예시단어 — 실제로 부수 분해가
길어지는 그 부분)의 `scale` 값 하나를 두 곳에서 직접 조절하게 했다:

1. **연습 화면 ⚙ 설정 팝오버**(`PracticeSettingsPopover.tsx`) — 기존 "라운드"/
   "채점 버튼" 행과 같은 스타일로 "한자 힌트 크기" 행을 추가(−/100%/+/기본값,
   0.8~1.6배, 10%씩).
2. **메인 설정 화면**(`more/settings/page.tsx`) — "오늘의 목표" 카드와 같은 스타일로
   "한자 크기" 카드를 추가(−/100%/+ 큰 버튼 + 아래에 실시간 미리보기 샘플 줄).

**주의해서 고친 버그**: `HintText` 컴포넌트는 원래 자기 내부에서 직접
`useHintTheme()`을 불러 저장값을 읽었다. 연습 화면 팝오버도 별도로
`useHintTheme()`을 부르면, 겉보기엔 같은 localStorage 키를 쓰지만 React
state로는 서로 다른 두 인스턴스가 되어 — 팝오버에서 조절해도 화면에 이미 떠 있는
힌트 텍스트(`HintText`)에는 그 자리에서 바로 반영되지 않고, 화면을 벗어났다
돌아와야만(리마운트돼야만) 보이는 문제가 생긴다. 그래서 `practice/page.tsx`
에서만 `useHintTheme()`을 한 번 불러 그 살아있는 `theme`을 `HintText`에 새로
추가한 선택적 `theme` prop으로 그대로 넘기게 바꿨다(prop을 안 주면 기존처럼
내부에서 자체적으로 불러오므로, `HintText`를 쓰는 다른 5개 화면은 그대로 동작).
메인 설정 카드는 팝오버와 동시에 화면에 떠 있을 일이 없는 별도 페이지라 이
문제가 없어서 그냥 자체 `useHintTheme()` 인스턴스를 썼다.

## 검증

`tsc --noEmit`·`eslint src/` 통과(도중 새 문단에 그대로 넣은 큰따옴표 때문에
`react/no-unescaped-entities` 에러가 나서 `&ldquo;`/`&rdquo;`로 교체). 크롬으로:

- 연습 화면(う동사 파일)에서 ⚙ 설정 팝오버의 "한자 힌트 크기"를 100→130%로 세
  번 눌러 올린 뒤 정답을 공개해, 한자 분해(음독/훈독/분해/어원, 노란색) 줄만 다른
  힌트 구간(읽기/종합/치트키/장면 등)보다 눈에 띄게 커진 것을 확대 캡처로
  확인 — 팝오버를 닫지 않고 값을 바꾼 바로 다음 렌더에서 반영됨(리마운트 불필요).
- `/more/settings`로 이동해 새 "한자 크기" 카드가 같은 값(130%)을 그대로 읽어와
  보여주고, 아래 미리보기 샘플도 커진 상태로 뜨는 것을 확인 — 페이지를 넘나들어도
  같은 localStorage 값을 공유하는 것 검증.
- 설정 카드에서 −를 세 번 눌러 100%로 되돌리고 `localStorage`의
  `word_app_hint_theme`이 기본값과 동일한 상태로 남아있는 것 확인(정리 완료).

## 기존 학습 DB에 미치는 영향: 없음

전부 기존에 있던 `hintTheme.ts`의 localStorage 저장 값(`kanji.scale`)을 조절하는
UI 진입점을 두 곳 늘린 것뿐이다. 새 저장 키·스키마·쿼리 없음.

## 3. (같은 날, 이어서) "한자 크기"가 힌트뿐 아니라 처음 질문 한자도 같이 바뀌게

## 요청 사항

"한자 크기조정을 힌트 한자만 하지말고, 처음 질문으로 나온 한자도 크기 바꿀 수
있도록 해줘"

바로 위(2번) 기능은 힌트의 한자 분해(음독/훈독/어원) 글자만 조절했는데, 연습 화면
카드 맨 위에 크게 나오는 질문(단어/한자) 자체는 별개의 값(`--practice-font-scale`,
화면별 글자 크기 조절 기능)이라 그대로 작았다. 두 값을 하나의 "한자 크기" 조절로
묶어달라는 요청.

## 구현

- `PracticeSettingsPopover.tsx`: "한자 힌트 크기" 행 이름을 "한자 크기"로 바꿨다
  (내부 값·범위는 그대로, 부모가 뭘 바꾸는지만 넓어짐).
- `practice/page.tsx`: 팝오버의 `onAdjustKanjiScale`/`onResetKanjiScale`가 이제
  `hintTheme.kanji.scale`뿐 아니라 이미 있던 `adjustFontScale`/`setFontScale`
  (연습 화면 카드 앞면 글자 크기, `word_app_practice_font_scale` /
  `--practice-font-scale`)도 같이 호출하도록 바꿨다. 두 값 다 기존에 있던 단일
  소스(useFontScale/useHintTheme)를 그대로 재사용했을 뿐이라, "글자 크기 설정"
  페이지의 "연습 화면" 행이나 카드 위 인라인 −/+/기본값 컨트롤과도 여전히 같은
  값을 공유한다 — 어디서 바꾸든 같은 저장소를 가리키므로 어긋날 일이 없다.
- `more/settings/page.tsx`의 "한자 크기" 카드도 같은 방식으로
  `useFontScale("word_app_practice_font_scale", "--practice-font-scale")`를
  추가로 불러 두 값을 함께 조절하게 했고, 설명 문구에 "연습 화면 질문 한자"도
  같이 조절된다는 내용을 추가했다. 이 카드에 "기본값" 칩 버튼도 새로 달아서
  두 값을 한 번에 100%로 되돌릴 수 있게 했다(이전엔 −/+ 만 있고 리셋 버튼이 없었음).
- 조절 범위는 두 값의 교집합인 힌트 쪽 범위(80~160%, 10%씩)를 그대로 따른다 —
  연습 화면 자체 인라인 컨트롤은 원래 180%까지 더 확대할 수 있는데, 그건 이
  "한자 크기" 지름길과 무관하게 계속 남아있다(더 키우고 싶으면 그 컨트롤이나
  "글자 크기 설정" 페이지를 쓰면 됨).

## 검증

`tsc --noEmit`·`eslint src/` 통과. 크롬으로 연습 화면(う동사 파일)에서 ⚙ 설정의
"한자 크기"를 100→130%로 올리고:

- 카드 앞면에 크게 나오는 질문 한자("養う")가 눈에 띄게 커진 것을 확대 캡처로 확인.
- 정답 공개 상태에서 힌트의 한자 분해(음독/훈독/분해, 노란색)도 같이 커진 것 확인.
- "기본값"을 눌러 두 값이 동시에 100%로 되돌아가고 질문 한자도 원래 크기로
  줄어드는 것 확인.
- 테스트로 바뀐 `word_app_hint_theme`(localStorage)·`word_app_practice_font_scale`
  (sessionStorage) 모두 기본값 상태인 것 확인 후 정리.

## 기존 학습 DB에 미치는 영향: 없음

전부 프론트엔드 표시 설정(localStorage/sessionStorage)이고, 기존에 있던 두
설정값(힌트 한자 크기, 연습 화면 글자 크기)을 같이 조절하는 진입점만 늘렸을 뿐
저장 방식 자체는 바꾸지 않았다.

## 4. (같은 날, 이어서) "한자 크기"에 [한자1]/[한자2] 제목 줄도 포함

## 요청 사항

사용자가 실제 힌트 예시(強引な / [한자1] 強 (강할 강…) / [한자2] 引 (끌 인…))를
들어 "強引な 랑 [한자1]…, [한자2]… 이 세 가지만 크기를 조절할 수 있는 기능을
'한자 크기' 기능에 넣어줘"라고 요청. 즉 지금까지 "한자 크기"가 조절하던 카드 앞면
질문 단어 + 힌트의 한자 분해 **본문**(음독/훈독/어원)에 더해, [한자1]/[한자2]…
**제목** 줄(`kanjiHeader` 구간, 원래 자기만의 별도 강조색·크기를 가진 구간)까지
같이 조절되게 해달라는 것 — 기존에 이미 잘 동작하던 본문·질문 단어 조절을 없애라는
뜻은 아니라고 판단해, 빼지 않고 세 번째 항목으로 추가했다.

## 구현

- `practice/page.tsx`·`more/settings/page.tsx`의 "한자 크기" 조절/리셋 핸들러에
  `updateHintTheme("kanjiHeader", { scale: ... })` 호출을 추가해, 이제 한 번의
  +/−/기본값으로 세 값(카드 앞면 질문 글자, `kanji` 본문, `kanjiHeader` 제목)이
  함께 바뀐다. `kanjiHeader`는 원래 기본 배율이 1.05(본문보다 살짝 큼)라 델타를
  더하는 방식으로 그 상대적 차이(제목이 본문보다 5%p 더 크다)를 그대로 유지한다.
  기본값 리셋은 각자 자기 기본값(질문 글자=1, 본문=1, 제목=1.05)으로 따로
  되돌아간다.
- 메인 설정의 "한자 크기" 카드 미리보기도 [한자1] 제목 줄 샘플(자기 색·크기 적용)과
  본문 샘플을 같이 보여주도록 확장했다.
- `PracticeSettingsPopover.tsx`·설정 카드 설명 문구에 "[한자1]/[한자2]… 제목 줄"도
  같이 조절된다는 내용 추가.

## 발견하고 고친 버그: 기본값 복원이 1.05가 아니라 1.1로 저장됨

`useHintTheme.update()`는 저장할 때 배율을 0.1 단위로 반올림하고 있었다
(`Math.round(x * 10) / 10`) — 원래 +/− 버튼이 0.1씩만 움직이니 문제가 없었는데,
이번에 "기본값" 리셋이 `kanjiHeader`를 1.05(0.1의 배수가 아님)로 직접 세팅하려고
하자 이 반올림 로직이 가장 가까운 0.1인 1.1로 밀어버렸다 — "기본값"을 눌러도
실제로는 기본값(1.05)이 아니라 1.1이 저장되는 버그였다. 크롬으로 확인하다가
localStorage 값을 직접 찍어봐서 발견했다. 반올림 단위를 0.1(`*10`)에서
0.05(`*20`)로 바꿔 고쳤다 — 0.1 단위 버튼이 만드는 값(1.0, 1.1, 1.2…)은 전부
0.05의 배수이기도 해서 이 변경으로 기존 +/− 동작은 전혀 안 바뀐다.

## 검증

`tsc --noEmit`·`eslint src/` 통과. 크롬으로:

- 연습 화면에서 [한자1] 항목이 있는 단어(否)를 펼쳐 "한자 크기"를 130%로 올리고,
  제목 줄("[한자1] 否 (아닐 부…)")이 본문(· 음독 등)보다도 눈에 띄게 더 큰 것을
  확대 캡처로 확인(제목=1.35, 본문=1.3 — 5%p 차이가 유지됨).
- "기본값"을 눌러 세 값 모두 원래대로 돌아가는 것 확인.
- 수정 전에는 리셋 후 `localStorage`의 `kanjiHeader.scale`이 `1.1`로 찍히는 버그를
  실제로 재현·확인했고, 반올림 단위 수정 후 정확히 `1.05`로 저장되는 것을
  `localStorage.getItem`으로 직접 읽어 검증했다.
- 메인 설정 "한자 크기" 카드의 새 2줄 미리보기(제목+본문)도 정상 렌더 확인.
- 테스트로 바뀐 localStorage/sessionStorage 값은 확인 후 전부 기본값 상태로
  정리했다.

## 기존 학습 DB에 미치는 영향: 없음

전부 힌트 테마 localStorage 값(`kanjiHeader.scale` 포함)과 연습 화면 글자 크기
sessionStorage 값을 다루는 프론트엔드 로직이다. 반올림 단위 변경은 값의 저장
정밀도만 0.1→0.05로 세분화한 것이라 스키마·쿼리와 무관하다.
