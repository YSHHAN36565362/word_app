## 1~2. 라운드/큐 설계 — 결론 (코드 변경 없음)

논의 끝에, 이미 구현된 큐 구조(`src/lib/queue.ts`)가 이 문제를 원천적으로 피해가고
있다는 걸 확인했다. "라운드"는 고정된 15개 단어 세트가 아니라 "연속으로 몇 번
성공(조금앎/완벽함)했는지"를 세는 진행률 개념이고, 선택한 단어 전체가 처음부터
한 큐에 다 들어있어서 모름/헷갈림 단어가 재등장하기 전에 항상 다른 단어들이
끼어든다. 그래서 "새 단어 잠금"이나 "모르는 단어 5개 이하면 새 단어 투입" 같은
추가 장치는 필요 없다고 판단해 구현하지 않았고, 현재 방식을 그대로 확정했다.
(자세한 내용은 `2026-08-30_11_log.md`의 관련 섹션에 갱신해둠.)

## 3. 같은 단어 연속/근접 반복 버그 수정

`requeuePosition`(모름/헷갈림 채점 시 재삽입 위치를 정하는 함수)에 실제 버그가
있었다 — 모름(0)으로 채점하면 일정 확률로 위치 0(맨 앞)이 뽑혀서 방금 본 단어가
바로 다음 카드로 또 나올 수 있었다. `queue.ts`에 `MIN_GAP = 3`을 둬서 최소
3개의 다른 단어를 거친 뒤에만 다시 나오도록 고쳤다(남은 단어가 1~2개뿐일 때는
가능한 최대 간격을 확보하도록 클램프 로직도 같이 손봄). 참고로 N2(Tr.Park_word)
1753개 중 脅かす·地味な·着替える·問い合わせる 4개 단어가 서로 다른 파일에
중복 등록돼 있었는데, 개수가 적어 원본 정리는 급하지 않다고 판단해 보류.

## 4. 글자 크기 조절 (1차: 연습 파트만)

연습 화면 카드 우상단(즐겨찾기·소리 왼쪽)에 `[−] 100% [+] [기본값]` 컨트롤 추가.
한자·뜻·힌트 텍스트가 80%~180% 사이에서 배율을 따르고, `sessionStorage`에 저장해
그 세션(탭) 동안 유지. 구현 중 개발 모드 React StrictMode가 마운트 effect를 두 번
실행하면서 복원된 배율 값이 기본값(100%)으로 도로 덮어써지는 버그를 실제로
재현해서 고쳤다(저장 시점을 "값이 바뀌는 자리"로 옮김). 같은 구조였던 "애니메이션
끄기" 체크박스도 함께 고쳤다.
(다음 날 이 기능을 학습/시험/지문 파트까지 공용 훅/컴포넌트로 확장함 —
`2026-09-01_10_log.md` 참고.)

## 6. 처음 사용자용 사이트 체험 투어

- 홈 화면에 "처음 시작하기" 버튼 추가 → `/more/guide`(사용법 설명)로 이동.
- 사용법 설명 페이지 맨 위에 "🚀 사이트 체험하기" 버튼 추가.
- `src/contexts/TourContext.tsx`(신규): 투어 진행 상태(활성 여부, 현재 스텝)를
  전역으로 관리. 스텝은 홈의 "학습 시작하기" 버튼 → 하단 탭(연습→매칭게임→
  시험→오답노트→설정)을 순서대로 짚어가는 6~7단계로 구성.
- `src/components/TourOverlay.tsx`(신규): 현재 스텝이 가리키는 실제 요소
  (`data-tour` 속성)를 찾아 빨간 테두리 박스로 감싸고(배경은 어둡게 스포트라이트
  처리), 화면 상단에 안내 문구, 하단엔 언제든 나갈 수 있는 빨간 "테스트
  종료하기" 버튼을 띄운다. 하이라이트 박스는 `pointer-events: none`이라 실제
  버튼 클릭을 가로막지 않고, 사용자가 그 버튼을 실제로 눌러 페이지가 이동하면
  경로 변화를 감지해 자동으로 다음 스텝으로 넘어간다.
- `BottomNav.tsx`에 탭별 `data-tour` 값 추가, 홈 화면 "학습 시작하기" 버튼에도
  `data-tour="home-study"` 추가.
- 크롬으로 전체 플로우(시작 → 6단계 진행 → 완료 카드, 중간 종료 포함) 직접 클릭
  검증 완료. 안내 문구가 하단 탭을 가리킬 때 "테스트 종료하기" 바와 겹치는 버그를
  발견해 문구 위치를 화면 상단 고정으로 수정.
