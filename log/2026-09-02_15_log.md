# 2026-09-02 작업 로그

## 요청 사항

1. 완벽함으로 채점해도 7일 후가 아니라 그날 바로 다시 나오거나, 심지어 바로 다음
   카드로 또 나오는 경우가 있다는 제보 — "써있는 대로 7일 후가 적용 안 되는 것
   같다". 완벽함은 아예 스택에서 빼버리고 앱에도 "완벽"이라고 표시해달라는 요청.
   조금 앎도 3일 후인데, 시간 기반으로 구현이 안 되면 "3일 후" 대신 "마지막에"처럼
   말을 바꿔달라는 요청. 난이도별로 스택이 잘 동작하는지 확인, 크롬 디버깅으로도
   확인 요청.
2. (이어서) 애니메이션 끄기를 기본값으로 바꿔달라는 요청.

## 1. 완벽함·조금 앎이 SRS 복습일 전에 다시 나오는 버그 — 두 가지 원인을 찾아 수정

원인을 나눠서 짚어보면 두 가지가 겹쳐 있었다.

**(1) 세션 시작 시 "복습일 전" 단어를 걸러내지 않고 뒤로 미루기만 했다.**
`mastery.ts`의 `prioritizeByMastery`가 SRS 복습 예정일(`nextReviewAt`)이 아직 안
지난 단어에 `NOT_DUE_PUSH`(30점)만 더해 뒤로 밀어내는 식이었다 — 완전히 빼는 게
아니라 "순서만 뒤로" 미루는 방식이라, 단어 수가 적은 단어장에서는 그 정도로는
부족해서 여전히 같은 날 다시 나오거나 세션 끝자락에서 걸리는 경우가 있었다.
`NOT_DUE_PUSH` 로직을 없애고, 새 함수 `excludeNotDue`(`mastery.ts`)를 만들어
세션을 시작하기 전에 완벽함(100)·조금 앎(60)이면서 복습일이 안 지난 단어를 그날
스택에서 **아예 제외**하도록 바꿨다. 다만 선택한 단어장 전체가 이미 채점되어
있으면 그날 연습할 단어가 하나도 없어져 버리는 게 더 나쁜 경험이라, 남는 단어가
5개(`MIN_DUE_FLOOR`) 미만이면 복습일이 가장 임박한 것부터 부족한 만큼만 다시
채워 넣는다.

이 필터는 파일을 골라 시작하는 일반 연습(`begin()`)에만 적용했다 — 오답
노트·즐겨찾기·"복습"(완벽함/조금 앎 전체를 다시 보는 화면)·"오늘의 복습"(서버에서
이미 날짜로 걸러서 옴)은 각자 목적상 날짜와 무관하게 보여줘야 해서 그대로 뒀다
(`startWithList`에 `applyDueFilter` 인자를 추가하고 `begin()`에서만 `true`로 넘김).

**(2) 원본 단어장 파일에 같은 단어가 중복 등재된 경우, 큐에도 사본이 두 장 이상
들어가 있었다.** 8/31 로그에서 이미 "N2 1753개 중 4개 단어가 중복 등록돼 있는데
개수가 적어 원본 정리는 보류"라고 남겨둔 문제인데, 실제로는 그 뒤로 그래머
단어장 등에 의도적으로 같은 문형(예: はずがない, かねない)을 여러 번 넣은 경우가
늘었다. 완벽함/조금 앎으로 채점해도 그 카드는 큐에서 빠질 뿐, 남아있는 사본은
그대로라 몇 장 뒤(운이 나쁘면 바로 다음 장)에 똑같은 카드를 또 만나게 됐다 —
"완벽함을 눌렀는데 바로 다음에 또 나온다"는 제보의 직접적인 원인. `queue.ts`에
`withoutKey` 헬퍼를 추가해, 100/60으로 채점할 때 큐에 남은 동일 단어(같은
word/meaning/hint) 사본을 전부 같이 제거하고 완료 개수에도 반영하도록
`practice/page.tsx`의 `score()`를 고쳤다. 원본 파일의 중복 자체는 그대로 둬도
이제 문제가 되지 않는다.

**버튼 문구는 그대로 뒀다.** "완벽함(100·7일 후)"/"조금 앎(60·3일 후)" 둘 다
`nextReviewAt`이라는 같은 메커니즘으로 실제 날짜 기준 필터링이 걸리므로, 요청에서
언급한 "시간으로 구현 안 되면 '마지막에'로 바꿔달라"는 대안(조금 앎용)은 쓸 필요가
없었다 — 두 문구 모두 이제 정확히 사실과 일치한다.

**"앱에도 완벽이라고 적어줘" 요청**은 두 군데에 반영했다.
- 연습 시작 화면: 오늘 스택에서 제외한 단어가 있으면 "완벽 N개 · 조금 앎 N개는
  아직 복습일이 안 돼서 이번 스택에서 제외했어요(완벽함은 7일 후, 조금 앎은 3일
  후 다시 나타나요)" 안내 배너를 보여준다. 선택한 단어장 전체가 제외 대상이면
  "오늘은 다 아는 단어뿐이에요! 🎉" 축하 문구로 대체한다.
- "복습" 화면(`more/review`): 단어마다 초록 "완벽"/파랑 "조금 앎" 배지와 "N일 후
  복습"(또는 "지금 복습 가능") 문구를 추가했다. 이 화면이 반환하는 타입도
  `WordEntry[]` → `MasteredWordEntry`(score·nextReviewAt 포함)로 확장했다
  (`loadMasteredWords`가 `word_mastery`에서 `score, next_review_at`도 함께 select).

**곁다리로 발견한 문서 오류도 고쳤다.** `mastery.ts` 주석엔 이미 "SM-2식 증가
간격 대신 점수별 고정값(0/0/3/7일)을 쓴다"고 정확히 적혀 있었는데, 정작
`more/review/page.tsx`, `UsageGuide.tsx`, 루트 `README.md`(한글+일본어 두 군데)엔
전부 "SuperMemo-2 방식, 1일→3일→7일...로 점점 늘어난다"는 옛날 설명이 그대로
남아있었다 — 실제 동작과 다른 설명이라 사용자가 "왜 7일 후라고 했는데 안
지켜지지" 오해할 소지가 있어서, 전부 "완벽함 7일 / 조금 앎 3일 고정"으로 고쳤다.

**검증**: `tsc --noEmit`·`eslint` 모두 통과. 실제 소스(`mastery.ts`/`queue.ts`)의
로직을 그대로 옮겨 적은 독립 스크립트로 6가지 시나리오(완벽함 당일 제외, 조금 앎
3일 제외, 복습일 지난 단어는 정상 노출, 전부 제외 시 최소 개수 fallback, 중복
큐 사본 제거, 약한 단어 우선 정렬 유지)를 unit-test 삼아 돌려 12개 assertion
전부 통과 확인. Supabase 없이도 되는 부분은 크롬(로컬 dev 서버, `localhost:3001`)
으로 직접 열어 확인 — 애니메이션 끄기 체크박스 기본 체크·마스코트 미노출,
연습 화면에서 완벽함 채점 시 진행률 정상 증가, 콘솔 에러 없음, "복습" 화면 정상
렌더까지 확인했다. 다만 이 환경엔 Supabase 동기화 저장소가 설정돼 있지 않아서(
설정 화면에 "현재 서버에 동기화 저장소가 설정되지 않아 진행 상황이 저장되지
않습니다" 경고가 뜸) `excludeNotDue`가 실제 DB 데이터로 걸러지는 것까지는 이
세션에서 확인하지 못했다 — 로직 자체는 위 unit-test로 검증했지만, 실제 배포
환경에서 완벽함으로 며칠 채점해보고 스택에서 잘 빠지는지 한 번 더 봐주면 좋겠다.

## 2. 애니메이션 끄기 기본값 변경

연습 화면 우상단 "애니메이션 끄기" 체크박스(마스코트 반응 일러스트 표시 여부)의
기본값을 `false`(켜짐) → `true`(꺼짐)로 뒤집었다. 기기별로 `localStorage`에
저장하는 방식은 그대로 두되, 저장된 값이 없으면 이제 "꺼짐"에서 시작한다. 이전에
명시적으로 "켜짐"으로 저장해둔 기기(저장값 `"0"`)는 그 선택을 그대로 존중한다.

## 3. (추가 요청) 채점 버튼 크기 조절 + 숨기기 — 대형 TV 대응

"윈도우 데스크탑을 대형 TV에 연결해서 쓸 때 연습 파트 채점 버튼(완벽함/조금 앎/
헷갈림/모름)이 너무 크다"는 요청. 글자 크기 조절(`useFontScale`, 세션 동안만
유지)과 똑같은 −/+/기본값 UI를 채점 버튼에도 만들되, 이번엔 요청대로 평소엔 작은
톱니바퀴(⚙) 버튼 하나만 채점 버튼 오른쪽 위에 떠 있다가, 누르면 작은 팝오버로
크기 조절 + 숨기기/나타내기가 펼쳐지는 방식으로 만들었다(버튼이 크다는 게
불만이라 조절 UI 자체가 상시 노출되면 본말전도라, "복잡한 리모컨" 대신 "평소엔
숨어있는 톱니바퀴"를 선택).

- `src/hooks/useScoreButtonPrefs.ts` (신규): scale(0.5~1.3, 기본 1)과
  hidden(기본 false)을 관리. 글자 크기와 달리 "거실 TV 전용 PC"처럼 한 번 맞춰두면
  계속 쓰고 싶은 기기별 설정이라, sessionStorage가 아니라 hideMascot과 같은
  localStorage에 저장.
- `src/components/ScoreButtonSizeControl.tsx` (신규): 톱니바퀴 트리거 + 팝오버.
  처음엔 −/%/+/기본값/숨기기/나타내기 6개를 한 줄에 다 넣었다가, absolute
  포지셔닝된 팝오버가 부모(톱니바퀴 버튼 하나 크기)의 좁은 flex 컨테이너 폭에
  눌려 글자가 한 자씩 세로로 쪼개지는 버그를 크롬에서 실제로 발견 — 팝오버 폭을
  `w-max`로 고정하고 두 줄(크기 조절 / 숨기기·나타내기)로 나눠서 해결.
- `src/app/practice/page.tsx`: 채점 버튼 grid를 감싸는 컨테이너에 톱니바퀴를 얹고,
  `transform: scale(scoreBtnScale)`(`transformOrigin: bottom center`, 버튼이 화면
  맨 아래 고정바에 있어서 아래쪽을 기준으로 줄어들게)로 버튼 전체(패딩·그림자·
  글자 크기 포함)를 한 번에 축소. `hidden`이면 버튼 grid 대신 "채점 버튼이
  숨겨져 있어요 — 키보드 1~4 또는 방향키로 채점하세요" 안내만 보여준다(기존
  키보드 단축키는 버튼 표시 여부와 무관하게 그대로 동작하므로 숨겨도 채점 자체는
  가능).

**검증**: `tsc --noEmit`·`eslint` 통과. 크롬으로 실제 조작해 확인 — 톱니바퀴 클릭 →
팝오버 두 줄 정상 렌더(줄 안 깨짐), `−` 3번 눌러 70%로 축소되는 것 확인, "숨기기"
클릭 시 버튼이 안내 문구로 바뀌고 콘솔 에러 없음, 숨긴 상태에서 키보드 `4`로
채점해 정상적으로 다음 카드로 넘어가는 것까지 확인, 새로고침 후 `localStorage`에
`scale:"0.7"`·`hidden:"1"`이 남아있어 기기별로 유지됨을 확인(테스트 후 초기화해둠).
