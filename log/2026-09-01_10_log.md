3. 예전에 연습 파트에만 넣은 글자 크기 조절(−/+/기본값) 기능을 모든 파트(학습/시험/

## 1. 9월 파일 인식 문제 — 원인은 캐시였음 (코드 수정 없음)

`extractYearMonth`(파일명에서 연/월을 뽑는 함수)와 월 그룹 라벨(`${연도}년 ${월}월`)은
처음부터 정규식 기반으로 완전히 범용적이라 특정 달을 하드코딩한 부분이 없었다.
실제 원인은 GitHub API 요청을 30명이 동시에 써도 요청 한도(시간당 60회)에 안
걸리게 5분 캐시(`revalidate: 300`)를 쓰고 있는데, 9월 파일을 막 커밋·푸시한
직후라 캐시가 아직 예전 목록을 들고 있었던 것. 캐시가 자연스럽게 갱신된 뒤
크롬으로 확인해보니 "2026년 9월 (1개)"가 8월보다 위에 정상적으로 떴다. 앞으로
10월/11월도 코드 수정 없이 그대로 인식되고, 다만 커밋 직후엔 최대 5분 정도
캐시 때문에 늦게 뜰 수 있다.

## 2. 연습 파트 "이어서 연습하기" — 여러 조합을 동시에 이어할 수 있게 구조 변경

**기존 동작**: `progress` 테이블이 (user_id, part)당 슬롯이 딱 하나였다. 그래서
A 단어장을 풀다가 나가고 B 단어장을 시작하면, A의 진행 지점이 통째로 덮어써져서
없어졌다 — "이 학습 다시 하기"로 A를 다시 골라도 처음부터 다시 섞여 시작됐다
(다만 단어별 숙련도(`word_mastery`)는 별도로 남아있어서 이미 아는 단어가 완전히
초기화되는 건 아니었음).

**변경 후**: `progress` 테이블 기본키를 `(user_id, part, file_key)`로 바꿔서,
연습 파트는 단어장 조합별로 각자 이어하기 지점을 남긴다.

- `supabase/schema.sql`: `progress` 테이블에 `file_key` 컬럼 추가, 기본키를
  `(user_id, part, file_key)`로 변경 (기존 학습/시험/지문 파트는 `file_key=''`
  한 슬롯만 그대로 씀 — 동작 안 바뀜).
- `src/lib/progress.ts`: `saveProgress`/`loadProgress`/`deleteProgress`에
  `fileKey` 선택 인자 추가(기본값 `""`), 새 함수 `listSavedProgress(userId, part)`
  추가 — 그 파트에서 아직 안 끝낸 진행 전부를 최근 순으로 돌려준다.
- `src/app/practice/page.tsx`: 단일 `saved` 상태를 `savedList` 배열로 바꾸고,
  파일 선택 화면 맨 위에 "이어서 연습하기 (N개)" 목록을 전부 카드로 보여준다.
  또한 `begin()`에서 선택한 파일 조합이 `savedList`에 이미 있으면 새로 섞어
  시작하는 대신 그 지점을 자동으로 이어간다 — "이전과 같은 단어장 목록을 누르면
  자동으로 이어서"가 이제 실제로 그렇게 동작한다. "이 학습 다시 하기"(대시보드
  드롭다운)도 같은 방식으로 고쳤다.

크롬으로 실제 테스트: 단어장 A에서 1개 채점 후 종료 → 다른 단어장 B로 바꿔서
1개 채점 후 종료 → 파일 선택 화면에 A, B 둘 다 "이어서 연습하기" 카드로 뜨는 것
확인. A를 다시 체크하고 시작 버튼(이어서 하기 카드가 아니라 일반 "한자 맞추기"
버튼)을 눌러도 처음부터 안 섞이고 정확히 멈췄던 지점(전체 1/202, 같은 단어)부터
이어지는 것도 확인.

(주의: 로컬 개발 서버의 `.env.local`에 Supabase URL/키가 비어 있어서, 이 기기의
`next dev`에서는 진행 상황이 실제로 서버에 저장되지는 않는다 — 페이지를
새로고침하면 목록이 사라진다. 화면 로직 자체는 검증됐지만, 실제 배포본에서
새로고침 후에도 남는지까지는 로컬에서 확인 못 했다. `.env.local`에 Supabase
anon key를 채워주면 그 부분까지 재검증 가능.)

## 3. 글자 크기 조절 기능을 학습/시험/지문 파트에도 적용

기존에 연습 파트에만 있던 −/+/기본값 글자 크기 컨트롤을 재사용 가능한 형태로
빼서 모든 카드 기반 파트에 적용했다.

- `src/hooks/useFontScale.ts` (신규): sessionStorage에 저장하는 글자 배율 훅.
  값이 바뀌는 자리에서만 storage에 쓰도록 만들어서(마운트 복원 effect는 읽기만
  함), 개발 모드 React StrictMode가 마운트 effect를 두 번 실행할 때 복원 값이
  기본값으로 덮어써지는 문제(직전에 실제로 재현됨)를 피했다.
- `src/components/FontSizeControl.tsx` (신규): `[−] 100% [+] [기본값]` UI를
  공통 컴포넌트로 분리.
- `practice/page.tsx`: 기존 인라인 구현을 이 훅/컴포넌트로 교체(동작 동일).
- `study/page.tsx`, `exam/page.tsx`, `script/page.tsx`: 카드 우상단(또는 위쪽)에
  같은 컨트롤 추가, 단어/뜻/힌트(또는 문장) 텍스트 크기가 배율을 따르도록 변경.

크롬으로 4개 파트(학습/연습/시험/지문) 전부 130%까지 올려서 실제로 글자가
커지는 것, 기본값 버튼으로 100%로 돌아오는 것 확인.

## 4. 단어장 원본(.txt) 파일에서 잘못된 단어 삭제 — 진행 중인 세션에 영향 없음

`word_test/word_list/Japanese/N2/2026-09-01_Tr.Park_word.txt`에서 잘못 들어간
`尊徳` 항목을 통째로 삭제해달라는 요청과 함께 "혹시 행(row)의 순서로 단어를
기억해서 섞고 있는 거라, 지금 누가 이 단어장으로 연습 중일 때 삭제하면 꼬이지
않을지" 질문이 있었다.

**결론: 안 꼬인다.** 이 앱은 어디에서도 "몇 번째 줄/몇 번째 단어"라는 위치 정보로
단어를 기억하지 않는다. 대신 항상 **단어+뜻+힌트 텍스트 전체를 하나의 값**으로
취급한다(`wordKey = word|meaning|hint`, `src/lib/queue.ts`). 근거:

1. **파일 파싱** (`src/lib/parser.ts`의 `parseWordText`): 빈 줄로 블록을 나누고,
   각 블록의 내용(1번째 줄=단어, 2번째 줄=뜻, 나머지=힌트)만 보고 그 자리에서
   `WordEntry`를 만든다. 인덱스나 줄 번호를 저장해두는 게 아니라, 파일을 다시
   읽을 때마다 "지금 이 순간 파일에 있는 블록들"을 처음부터 새로 만든다. 그래서
   중간에 있던 블록 하나(尊徳)를 통째로 지워도 앞뒤 블록(尊敬, 殻)은 원래
   내용 그대로 다시 만들어질 뿐이고, "밀림"이나 "뒤섞임" 같은 건 애초에
   일어날 수 없는 구조다.
2. **이미 진행 중인 세션**: 연습을 시작하는 순간 GitHub에서 그 시점의 파일
   내용을 한 번 받아와서(fetchWords) 브라우저 메모리에 통째로 올려두고 섞는다
   (`shuffle`). 그 뒤로는 세션이 끝날 때까지 원본 파일을 다시 들여다보지
   않으므로, 연습 도중에 원본 파일을 고쳐도 지금 보고 있는 큐에는 전혀 영향이
   없다 — 이미 받은 尊徳도 그 세션 안에서는 계속 그대로 나온다.
3. **저장된 "이어서 연습하기" 진행**(어제 새로 만든 기능): 큐 자체를(단어
   원문 전체를 포함해서) 통째로 스냅샷으로 저장해두기 때문에, 나중에 그 진행을
   이어가도 저장 시점 그대로 복원된다 — 원본 파일이 바뀌었다고 저장된 진행이
   깨지지 않는다.
4. **단어별 숙련도(`word_mastery`)·즐겨찾기·오답노트**: 전부 `wordKey`(단어+뜻+
   힌트 내용)나 단어 원문 자체를 저장해두는 방식이라, 원본 파일에서 그 단어를
   지워도 이미 쌓인 기록이 깨지거나 다른 단어에 잘못 붙는 일은 없다. 다만 지운
   단어에 대한 숙련도 기록은 이제 어디서도 다시 매칭될 일이 없는 "고아 데이터"로
   조용히 남는데(에러는 아니고 그냥 안 쓰이는 행), 완전히 정리하고 싶으면
   나중에 필요할 때 요청하면 지울 수 있다.

즉 형식(빈 줄로 블록 구분)만 유지한 채 항목 하나를 통째로 지우는 건 언제 해도
안전하다 — 실제로 요청하신 대로 尊徳 블록을 삭제해서 尊敬 → 殻 순서로 바로
이어지게 반영했다(202개 → 201개, `殻` 앞에는 빈 줄 하나만 남도록 정리).
