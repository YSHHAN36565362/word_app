# 프롬프트: IT 용어 단어장 만들기 (질문형 / 일본어 IT 용어형)
# [예문] 연습 간격: 한국어 → (간격줄 2개) → 일본어 → (간격줄 2개) → 히라가나. 간격줄은 U+200B 한 글자 줄(진짜 빈 줄은 카드를 쪼갬).
# 사용법: "----- 프롬프트 시작 -----" ~ "----- 프롬프트 끝 -----" 사이를 AI에 붙여 넣고, 맨 아래 Input Data의 [ ] 부분에 목록을 넣는다.
# 결과를 받으면: 맨 끝의 "=== 완료율/진행률 ===" 줄(카드 목록 아님)은 지우고, 질문형은 word_list/_IT/<세부폴더>/, 일본어 IT 용어형은 word_list/_IT/IT/ 에 YYYY-MM-DD_이름.txt 로 저장한다.
# 저장 후 GitHub Desktop으로 커밋·푸시 → Vercel 재배포(1~2분) 후 앱에 나타남.
# 토큰 한도로 끊기면 완료율 줄의 "다음" 항목부터 이어서 다시 요청한다.

----- 프롬프트 시작 -----
Role
당신은 IT 자격증(정보처리기사·빅데이터분석기사 등)과 일본 IT 면접을 가르치는 강사입니다.
당신의 결과물은 word_app(Next.js 기반 단어 암기 앱)의 힌트 파서가 그대로 읽는 .txt 카드 목록입니다.
두 가지 유형 중 입력에 지정된 유형만 사용하십시오.
· A유형(질문형): 앞면에 정의를 묻는 질문, 뒷면에 정답 용어 (자격증용)
· B유형(일본어 IT 용어형): 앞면에 일본어 IT 용어, 뒷면에 한국어 뜻 (일본 IT 면접·실무용)

=== 절대 준수: 파싱 안전 규칙 ===
1. 한 카드 = 빈 줄 없는 연속된 줄 묶음. 카드 내부에 진짜 빈 줄 절대 금지(예외: B유형 [예문]의 간격줄 U+200B 줄). 카드와 카드 사이만 빈 줄 정확히 1개.
2. 1번째 줄은 앞면(문제), 2번째 줄은 정답, 3번째 줄부터 힌트입니다. 1번째 줄에 콜론(":", "：")·정답·읽는 법을 노출하지 마십시오.
3. 마크다운(**, *, #, 코드블록, 표) 금지, 부등호 < > 금지, 전각 ＋ 금지. 목록 기호는 "·"만 사용.
4. 힌트 태그는 정확히 일치하는 문자열만: [종합] [치트키] [헷갈리는 단어] [읽기] [한자1] [예문]
   (이 프롬프트 한정으로 [구분] [주의]도 허용 — 앱에서는 "그 외" 구간으로 표시됩니다.)
5. 카드 사이에 인사말·설명·진행 상황을 끼워 넣지 마십시오.
6. B유형 [예문] 연습용 간격 규칙 (한국어→일본어 해석 연습, 일본어→요미가나 읽기 연습용)
   [예문]은 반드시 아래 순서로 쓰고, 덩어리 사이를 "두 줄 띄운" 것처럼 보이게 합니다.
     ① 첫 줄: [예문] "한국어 번역"   (한국어가 먼저. 따옴표 안에는 한국어 번역만)
     ② 간격줄 2개
     ③ 일본어 예문 한 문장 (태그 없이 문장만)
     ④ 간격줄 2개
     ⑤ 그 일본어 문장 전체의 히라가나 독음 (띄어쓰기 없이, 구두점 유지, 태그 없이 독음만)
   · 간격줄 = 보이지 않는 문자 U+200B(제로폭 공백) 한 글자만 들어 있는 줄입니다.
     템플릿의 【간격줄】은 이 줄을 뜻하므로 "【간격줄】"이라는 글자를 그대로 출력하지 말고 U+200B 한 글자만 있는 줄로 바꿔 쓰십시오.
   · 진짜 빈 줄(글자가 전혀 없는 줄, 일반 공백·전각 공백·NBSP만 있는 줄)은 앱 파서가 카드 구분자로 읽어 카드를 둘로 쪼개므로 절대 쓰지 마십시오.
     (파서는 줄마다 trim()을 하지만 U+200B 는 지워지지 않아 카드가 끊기지 않고, 화면에서는 빈 줄로 보입니다.)
   · ③·⑤의 태그 없는 줄은 바로 위 [예문] 구간에 속해, 같은 색·같은 숨김 설정을 따르며 앱에서 블러(마우스를 올리면 표시) 처리됩니다.
   · [예문]을 여러 개 쓸 때는 ①~⑤ 한 세트를 통째로 반복하고 세트 사이에도 간격줄 2개를 둡니다.

=== A유형(질문형) ===
1줄째: 정의·특징을 설명하는 질문 한 문장. 끝은 "~은?"/"~는?". 정답이 바로 떠오르도록 구체적으로.
2줄째: 정답 용어 한국어(영문 풀네임/약어)  예: 프로그래밍 언어 (Programming Language)
[종합] 개념 풀이 1~3줄. 구성요소·분류를 나열할 때는 "· " 줄로.
[치트키] 두음·연상 암기법. 두음 암기는 "A-B-C → 의미" 형태로, 그 연상 문장이 정말 해당 용어의 철자·순서와 맞는지 확인.
[구분] (선택) 헷갈리는 개념과의 차이 1줄
[주의] (선택) 시험에서 자주 틀리는 포인트 1줄

=== B유형(일본어 IT 용어형) ===
1줄째: 일본어 IT 용어 (예: 排他制御, レイテンシ)
2줄째: 한국어 뜻(히라가나 독음)  예: 배타 제어(はいたせいぎょ)
[읽기] 한자어일 때 한자1=실제읽기(음독/훈독 구분, 원형 읽기, 형태) + 한자2=… → 전체 독음. 가타카나어는 이 줄 생략.
  · 각 한자의 괄호에는 반드시 ① 음독/훈독 ② 사전의 원형 읽기 ③ 형태를 적는다.
  · 형태는 다음 중 하나로만 쓴다: 원형 그대로 / 탁음화(연탁) / 반탁음화 / 촉음화 / 음편 / 기타 변형.
    원형 그대로여도 "원형 그대로"라고 반드시 명시한다(생략 금지).
  · 변형이면 "원형→실제읽기"로 적는다. 예: 学=がっ(음독 ガク→がっ: 촉음화) / 人=びと(훈독 ひと→びと: 탁음화(연탁))
    변화 원인이 불분명하면 지어내지 말고 "기타 변형"이라고만 쓴다.
[한자1] 한자 (한국식 훈음 / 뜻) — 한자어일 때만. 하위 줄: · 음독 · 훈독 · 이 단어에서의 읽기(실제읽기 — 음독/훈독, 원형 읽기, 형태) · 분해(강희 214부수 기준, 확신 없으면 "형태 미상") · 어원. 한자가 더 있으면 [한자2], [한자3] …
[종합] 개념 설명 1~2줄 + 영어 원어 (예: 영어: exclusive control)
[예문] "한국어 번역"
【간격줄】
【간격줄】
면접·실무에서 쓰는 일본어 문장
【간격줄】
【간격줄】
그 일본어 문장의 히라가나 독음(띄어쓰기 없이, 구두점 유지)
[헷갈리는 단어] (선택) 비슷한 용어(읽기) - 차이 1줄

=== 내용 정확성 원칙 ===
· 버전·법규·시험 범위처럼 바뀔 수 있는 정보는 단정하지 말고, 확실하지 않으면 그 줄을 생략하십시오.
· 약어는 반드시 풀네임을 함께 쓰고, 영어 표기는 영문 그대로 쓰십시오.
· 같은 용어를 질문 표현만 바꿔 중복 생성하지 마십시오. 입력 순서를 바꾸지 마십시오.

=== 완료율 ===
모든 카드 출력이 끝난 뒤, 빈 줄 2개를 넣고 별도 한 줄로 표기하십시오(카드 목록과 분리).
=== 완료율: [처리 수] / [전체 수] ([%]) | 다음 항목: [이름] ===
토큰 한도로 멈추면 마지막으로 완전히 끝난 카드에서 끊고, 다음 요청에서 이어서 작성합니다.

=== 예시 ===
(A유형)
주어진 문제를 해결하기 위해 인간과 컴퓨터 사이에서 의사소통을 가능하게 하는 인공적인 언어는?
프로그래밍 언어 (Programming Language)
[종합] 간결성, 가독성, 정확성, 기계 독립성 등이 주요 특성입니다.
[치트키] 사람과 컴퓨터의 통역사

(B유형)
排他制御
배타 제어(はいたせいぎょ)
[읽기] 排=はい(음독 ハイ: 원형 그대로) + 他=た(음독 タ: 원형 그대로) + 制=せい(음독 セイ: 원형 그대로) + 御=ぎょ(음독 ギョ: 원형 그대로) → はいたせいぎょ
[종합] 여러 트랜잭션이 같은 데이터를 동시에 갱신해 생기는 불일치를 막기 위해 락으로 접근을 제한하는 제어. 영어: exclusive control
[예문] "배타 제어로 데이터 정합성을 유지합니다"
