## 2. 폴더 → 메뉴 매핑

```
word_list/
  <대분류>/                 예: Japanese, _IT
    <세부카테고리>/          예: N2, N3, IT, 정보처리기사_실기
      <파일>.txt
```

- 대분류 > 세부카테고리 > 파일 순으로 선택 화면에 나타난다. `Japanese`는 항상 맨 앞.
- 세부카테고리 폴더가 하나라도 있으면, 대분류 바로 아래에 둔 `.txt`는 목록에서 **무시**된다. 반드시 세부카테고리 폴더 안에 넣을 것.
- `.txt` 확장자만 인식한다. 이름순(`localeCompare`) 정렬.
- 파일명이 `YYYY-MM-DD`로 시작하면 파일 선택 화면에서 "2026년 10월"처럼 월별 그룹으로 묶이고(최신 월이 위, 월 안에서는 파일명 내림차순), 날짜가 없으면 "날짜 없음" 그룹으로 간다. 예: `2026-10-28_Tr.Park_Word.txt`.
- 파일명에 `\ / : * ? " < > |`가 있으면 업로드 시 `_`로 바뀐다. `.txt`가 없으면 자동으로 붙는다.

## 3. 파일 형식 (파서 규칙)

**빈 줄 = 단어 하나의 끝.** 단어 하나는 "블록"이고, 블록 사이는 빈 줄 하나 이상으로 구분한다. 각 줄은 앞뒤 공백이 제거된다. 전각 콜론 `：`은 `:`로 바뀐다. CRLF/LF 둘 다 가능.

### 형식 B (줄 구분, 권장 — 기존 단어장 대부분)

```
단어(앞면에 나오는 질문)
뜻(정답)
힌트 1줄째
힌트 2줄째
…
```

- 1줄째 = 단어, 2줄째 = 뜻, 3줄째부터 전부 = 힌트(여러 줄 가능, 줄바꿈 유지).
- 블록이 1줄뿐이면 업로드 시 "뜻이 없는 단어" 오류.

### 형식 A (콜론)

```
단어 : 뜻
힌트 1줄째
힌트 2줄째
```

- **첫 줄에 `:`가 있으면 무조건 형식 A로 처리된다.** 형식 B의 단어/질문 줄에 `:`가 들어가면 `:` 앞뒤로 쪼개져 잘못 읽힌다. 질문에 콜론이 필요하면 쓰지 말고 `-`나 `,`로 바꿀 것. (예: `시간: 3시` ✗)
- 첫 `:` 하나만 구분자다. 뜻 안의 `:`는 괜찮다.

### 검증·중복

- 단어가 비었거나 뜻이 비면 업로드 오류(몇 번째 줄인지 알려 줌). 힌트는 비어도 된다.
- **(단어, 뜻, 힌트) 세 값이 모두 같은 항목**만 중복으로 제거된다. 같은 단어라도 뜻이나 힌트가 다르면 별개 카드로 취급되어 따로 출제된다. 학습 기록의 키도 이 세 값을 `|`로 이은 문자열이다 → **이미 학습한 단어의 텍스트를 고치면 새 단어로 간주되어 기록(숙련도·SRS)이 초기화**된다.
- 여러 파일을 함께 선택해도 같은 규칙으로 합쳐서 중복 제거한다.

### 지문 암기(`/script`) 전용

같은 파일을 지문으로 열면 **빈 줄이 아닌 모든 줄이 한 줄씩** 암기 대상이 된다. 지문용 파일은 위의 단어 형식이 필요 없고, 한 줄에 한 문장씩 쓰면 된다.

## 4. 힌트 태그 규칙 (앱이 색·크기·숨김을 적용하는 방식)

힌트 줄이 `[태그]`로 시작하면 앱이 구간으로 인식해 굵게 표시하고, 사용자가 구간별로 색/크기/숨김을 설정할 수 있다. 태그가 없는 줄(`· 음독: …` 등)은 **바로 앞 태그의 구간을 이어받는다**(구간을 숨기면 하위 줄도 같이 숨겨짐).

| 태그(줄 맨 앞) | 구간 | 용도 / 기존 단어장의 쓰임 |
|---|---|---|
| `[읽기]`, `[악센트]` | 읽기·악센트 | 히라가나 읽기, 음독/훈독 구분, 한자별 읽기 분해 |
| `[한자1]`, `[한자2]` … | 한자 항목(제목 줄은 별도 강조 가능) | `[한자1] 売 (팔 매 / 팔다)` 뒤에 `· 음독:`, `· 훈독:`, `· 분해:`, `· 어원:`, `· 예시단어(음독):` 줄이 이어짐. 숫자는 무시되고 구간은 같음 |
| `[종합]` | 종합 설명 | 여러 줄 가능 |
| `[치트키]` | 암기 치트키 | 말장난·연상 암기법 |
| `[장면]` | 장면 이미지 | 머릿속에 그리는 상황 묘사 |
| `[예문]`, `[예문1]` … | 예문 | 예문 + 읽기 + 번역 |
| `[활용]` | 활용형 | 동사·형용사 활용 |
| `[헷갈리는 단어]` | 헷갈리는 단어 | 비슷한 단어와의 구분 |
| `[유래]` | 그 외 | 어원 |
| 그 외 `[의미]`, `[구성]`, `[구분]`, `[주의]` 등 | 그 외(회색 기본) | 자유 사용, 인식은 되지만 전용 설정 없음 |

사용 빈도(현재 `word_list` 전체 기준): 한자N 9,576 · 예문 7,050 · 치트키 6,805 · 종합 6,204 · 장면 5,897 · 읽기 5,223 · 헷갈리는 단어 1,666 · 활용 1,159 · 악센트 910 · 의미/구성 각 850 · 구분 597 · 유래 100.

규칙 요약
- 태그는 **줄의 맨 앞**에 `[태그]` 형태로. 태그와 내용은 같은 줄에 써도 된다 (`[읽기] 値=あたい + する → あたいする`).
- 태그 이름 오타(`[치트기]` 등)는 "그 외" 구간으로 떨어져 색 설정이 안 먹는다. 위 표의 이름을 정확히 쓸 것.
- 힌트 안에 **빈 줄을 넣지 말 것.** 빈 줄이 나오면 거기서 단어가 끝나고, 이어지는 줄이 새 단어로 읽힌다.
- 힌트는 마크다운이 아니라 **일반 텍스트**다. `**굵게**`, `#` 같은 기호는 그대로 화면에 찍힌다. 목록 기호는 `·` 또는 `-`를 쓴다.
- 줄이 길어도 자동 줄바꿈된다. 모바일 기준으로 한 줄은 짧게 쓰는 편이 읽기 좋다.

## 5. 화면에서 단어 하나가 쓰이는 방식

- **앞면(질문)**: 1줄째. 한 줄로 짧고 명확하게. 발음 듣기(TTS) 버튼이 이 텍스트를 읽는다 → 일본어 단어는 일본어 표기 그대로.
- **정답**: 2줄째. 채점(완벽함/조금 앎/헷갈림/모름)은 사용자가 직접 정한다. 뜻은 한 줄로, 필요하면 괄호 안에 읽기를 붙인다 (`매출이 늘다(うりあげがのびる)`).
- **힌트**: 3줄째부터. 정답을 연 뒤 표시된다.
- **매칭 게임/시험**: 단어↔뜻 쌍으로 쓰므로 **뜻이 한 줄이고 짧을수록** 보기 좋다. 한 파일 안에서 같은 뜻이 서로 다른 단어에 중복되면 보기에서 헷갈린다.
- **숙련도·SRS**: (단어|뜻|힌트)가 키. 한 번 배포한 단어장의 텍스트는 가급적 수정하지 말고, 새 단어는 새 파일(또는 새 날짜 파일)로 추가.
- **크기**: 파일 하나에 수백~수천 개도 가능(현재 가장 큰 단어장은 N2 계열). 다만 학습 모드는 라운드 단위로 쪼개 진행하므로 한 파일을 몇 백 개 단위로 나누면 선택이 편하다.

## 6. AI에게 줄 프롬프트 뼈대

아래를 복사해서 `{ }` 부분만 채운다.

```
너는 일본어 IT 연수생을 위한 암기용 단어장을 만드는 도우미야.
아래 [출력 규칙]을 정확히 지켜서 {주제/교재/범위}의 단어 {개수}개를 만들어 줘.

[출력 규칙]
1. 출력은 코드블록 하나(```text)에 일반 텍스트만. 설명·머리말·마크다운 기호 금지.
2. 단어 하나 = 블록 하나. 블록 사이는 빈 줄 한 줄. 블록 안에는 빈 줄 금지.
3. 블록 형식:
   1줄째: 단어 (콜론 ":" 사용 금지)
   2줄째: 한국어 뜻 (한 줄, 필요하면 괄호 안에 히라가나 읽기)
   3줄째부터: 힌트. 각 줄은 아래 태그 중 하나로 시작하고, 태그가 없는 줄은 바로 위 태그에 이어지는 내용이다.
   [읽기] 한자별 읽기 분해 → 전체 읽기 (음독/훈독 표시)
   [한자1] 한자 (음 / 뜻)  ← 한자마다 [한자2], [한자3] …
   · 음독: …   · 훈독: …   · 분해: …   · 어원: …   · 예시단어(음독): …   · 예시단어(훈독): …
   [종합] 한자 뜻을 엮어 단어 뜻을 설명
   [치트키] 한국어 발음 말장난 등 연상 암기법
   [장면] 떠올리기 쉬운 상황 한 문장
   [예문] 일본어 문장 (읽기) / 한국어 번역
   [활용] (동사·형용사일 때만) 활용형
   [헷갈리는 단어] (있을 때만) 비슷한 단어와 차이
4. 태그 이름은 위 표기 그대로 쓴다. 다른 태그를 만들지 않는다.
5. 단어(1줄째)와 뜻(2줄째)이 같은 항목은 만들지 않는다. 이미 있는 단어 목록: {중복 제외할 단어들}
6. 사실이 불확실한 어원·분해는 지어내지 말고 해당 줄을 생략한다.

[예시]
値する
~할 가치가 있다(あたいする)
[읽기] 値=あたい + する(동사화 어미) → あたいする (훈독)
[한자1] 値 (값 치 / 값, 가치)
· 음독: チ
· 훈독: ★あたい, ね
· 분해: 亻(사람 인) + 直(곧을 직, 발음요소)
· 어원: 사람이 물건을 곧게 평가한 값을 나타냄
· 예시 단어: 価値 (가치, か+ち)
[종합] 値(값 치)에 する가 붙어 동사화된 형태로, 무언가가 그럴 만한 가치를 지님을 뜻함
[치트키] "아타이스루! 아타이(가치)가 있다 스루"
[장면] 큰 상을 받을 만한 훌륭한 업적을 이룬 장면
[예문] 賞賛に値する成果だ (쇼산니 아타이스루 세이카다) / 칭찬받을 만한 성과다
```

IT 자격증처럼 **질문형 단어장**(`_IT` 계열)을 만들 때는 3~4번을 다음처럼 바꾼다.

```
1줄째: 질문 또는 설명 (예: "컴퓨터가 무엇을 어떻게 처리해야 할지를 지시하는 명령어 집합은?")
2줄째: 정답 (예: "컴퓨터 프로그램 (Computer Program)")
3줄째~: [종합] 풀이, [치트키] 암기법 (필요한 태그만)
```

## 7. 만든 결과를 앱에 넣는 방법

1. **앱에서 추가**: 더보기 > 단어장 추가 → 대분류/세부카테고리 선택 → 제목(파일명) 입력 → 내용 붙여넣기 → 비밀번호 입력. 형식 오류가 있으면 줄 번호와 함께 알려 준다. 성공하면 `word_app` 저장소에 커밋되고 **Vercel 재배포가 끝나면** 목록에 나타난다.
   - 이 경로가 동작하려면 Vercel의 `GITHUB_REPO`가 `word_app`이어야 한다.
2. **파일로 직접 추가**: `word_app/word_list/<대분류>/<세부카테고리>/날짜_이름.txt`로 저장 → 커밋·푸시 → 재배포. 로컬 `npm run dev`에서는 저장 즉시(최대 5분 캐시) 보인다.
3. 새 세부카테고리가 필요하면 폴더를 새로 만들고 안에 `.txt`를 넣는다(앱 추가 화면은 기존 폴더만 고를 수 있음).

## 8. 체크리스트 (AI 결과를 넣기 전)

- [ ] 빈 줄은 단어와 단어 사이에만 있다 (힌트 안에 빈 줄 없음)
- [ ] 1줄째에 `:` 또는 `：`가 없다
- [ ] 모든 단어에 2줄째(뜻)가 있다
- [ ] 태그 이름이 표의 표기와 정확히 같다
- [ ] 마크다운 기호(`**`, `#`, 백틱)가 섞이지 않았다
- [ ] 파일명이 `YYYY-MM-DD_이름.txt` 형태이고 금지 문자가 없다
- [ ] 이미 학습 중인 단어를 고친 것이 아니라 새 항목/새 파일이다
