## 1. 오늘의 목표 상한 확대(200 → 500) + 자주 쓰는 값 프리셋

하루 200개+ 하는 사용자에게 기존 상한 200은 애초에 목표를 다 담지 못하는 값이라,
`DAILY_GOAL_MAX`를 500으로 올렸다. +/− 버튼도 30개 아래면서 세밀 조절 원할 확률이
높은 구간(50 미만)은 5개씩, 그 위(자주 100~200대를 오갈 것)는 10개씩 움직이도록
`goalStepFor()`를 추가했다. 매번 버튼을 몇 번씩 누르지 않도록 30/50/100/150/
200/300개 프리셋 칩도 목표 카드 아래 추가했다(설정 화면, 크롬으로 200 클릭 확인).

## 2. 라운드 크기(연습 파트) 조절 — `useRoundSize`

`queue.ts`의 `ROUND_SIZE=15` 하드코딩 상수를 그대로 쓰던 `requeuePosition`에
`roundSize` 매개변수를 추가하고 기본값만 기존 상수로 유지해, 호출부(연습 화면)가
원하는 값을 넘길 수 있게 했다. 연습 화면에는 5~50개 사이 +/−/기본(15) 조절을
추가했고, 헷갈림·모름 단어가 몇 라운드 뒤에 다시 나올지도 이 값을 그대로 따라간다.
기기별 localStorage 값이라 학습 기록과는 무관하다. 크롬에서 15→5로 낮춰 라운드가
실제로 5개마다 완료 화면을 띄우는 것까지 확인했다.

이 조절 UI와, 지난번에 만든 채점 버튼 크기/숨기기, 애니메이션 끄기를 전부 톱니바퀴
하나(`PracticeSettingsPopover`)로 합쳤다 — 예전엔 애니메이션 체크박스가 진행바
위에 상시 노출돼 있었는데, 학습 중 늘 볼 필요는 없어서 접어 넣었다.

## 3. 듀오링고식 세션 요약 화면 — `SessionSummary`

"대기열의 모든 연습을 완료했습니다." 한 줄이 전부였던 완료 화면을, 이번 세션에서
완벽함/조금 앎/헷갈림/모름을 각각 몇 번 눌렀는지 보여주는 요약으로 바꿨다(채점
횟수 총합·소요 시간·완벽+조금 앎 비율도 함께). 채점할 때마다 로컬 `tally` state에
집계하다가(서버에는 안 씀 — 이미 word_mastery에 개별 저장되고 있어 중복 불필요),
세션 시작/이어하기 시 초기화한다. `Date.now()`를 렌더 중에 부르면 안 되는
린트 규칙 때문에, 소요 시간은 "완료된 순간"에 effect로 한 번만 재서 고정.
크롬으로 실제 23개 단어(라운드 크기 5로 낮춘 채) 끝까지 풀어서 "채점 25회 ·
2분 35초 · 완벽·조금 앎 비율 92%"에 21/2/1/1 분포 막대까지 정상 확인.

## 4. 힌트 구간별 테마(색·크기·숨김) — `hintTheme.ts` / `HintText.tsx`

요청 원문: "한자1과 한자2가 멀리 떨어져있으니 이 한자 파트의 시작 줄만 색깔을
다르게" + "테마(한자 뜻, 단어 뜻, 치트키, 예문 등 색깔·크기), 원하지 않는 설명은
안 보이게".

실제 단어장(word_test 쪽 여러 세션에서 만든 N2/N1 등) 힌트 형식을 다시 훑어보니
`[읽기]`/`[한자N]`/`[종합]`/`[치트키]`/`[장면]`/`[예문]`/`[활용]`/`[헷갈리는 단어]`
대괄호 태그가 항상 줄 맨 앞에 오는 일정한 구조였다. 이 태그로 줄을 9개 구간으로
분류하고(`sectionOfLine`), 태그 없는 줄(예: `· 음독:`)은 직전 줄의 구간을 그대로
물려받게 해서 하위 항목이 통째로 같이 숨겨지거나 강조되게 했다.

- `src/lib/hintTheme.ts` (신규): 구간 목록·기본 테마·localStorage 저장/불러오기.
- `src/hooks/useHintTheme.ts` (신규): React 훅 래퍼.
- `src/components/HintText.tsx` (재작성): 예전 버전은 "대괄호만 있는 줄"만
  강조하도록 정규식을 짜뒀는데, 실제 데이터는 `[읽기] 従=したが + う → …`처럼
  태그와 내용이 한 줄에 붙어 있어서 그 정규식이 사실상 한 번도 매치가 안 됐다 —
  즉 지금까지 강조 기능 자체가 죽어 있었다. 태그가 줄 시작에 있으면 인식하도록
  고쳤다.
- `src/components/HintThemeSettings.tsx` (신규): 구간마다 보이기 체크박스·−/+
  크기(80~160%)·색상 6종 칩·실시간 예시 줄. 설정 화면 맨 위(오늘의 목표 다음)에 배치.
- **한자 항목 제목 강조** (요청 2번): "한자" 구간을 제목 줄(`kanjiHeader`)과
  본문(`kanji`, 음독/훈독/분해/어원/예시단어)으로 다시 나눴다. `kanjiHeader`의
  `visible`은 다른 구간과 뜻이 달라 — 끄면 그 줄이 사라지는 게 아니라 kanji 구간과
  같은 색으로 섞여 보일 뿐이다(제목 줄만 없애면 그 아래 음독/훈독이 어느 한자
  것인지 알 수 없게 되어버리므로). 기본값은 빨간색·105% 크기로, 다른 구간과
  뚜렷이 구분되게 했다.

크롬으로 실제 N2 단어(叶う) 힌트를 열어 확인 — `[읽기]` 파랑, `[한자1]` 빨강(제목
줄만), 음독/훈독/분해 등 하위 줄은 기본색, `[종합]` 기본색, `[치트키]` 초록,
`[장면]` 기본색, `[예문]` 노랑으로 구간마다 다르게 렌더되는 것을 눈으로 확인했다.

## 검증

`tsc --noEmit`·`eslint src/` 전체 통과(에러 0). 크롬 dev 서버로 설정 화면(목표
프리셋·힌트 테마 패널), 연습 화면(설정 팝오버 4행·라운드 크기 실시간 반영·한자
헤더 강조·라운드 완료 화면·세션 요약 화면)까지 전부 조작해서 확인, 콘솔 에러
없음. 테스트로 만졌던 localStorage 값(목표·라운드·채점 버튼·힌트 테마 등)은
확인 후 전부 지워서 기본값 상태로 돌려놨다.

## 기존 학습 DB에 미치는 영향: 없음

이번에도 전부 localStorage(기기별 취향값) + `requeuePosition`의 매개변수화뿐이라
스키마·쿼리 변경이 없다. `queue.ts`의 `requeuePosition` 시그니처에 세 번째 인자
`roundSize`가 추가됐지만 기본값(`ROUND_SIZE`)이 있어 기존 호출부는 그대로
동작한다(연습 페이지만 명시적으로 넘기도록 고쳤음).

## 5. (같은 날, 이어서) "내 번호 저장했는데 이어하기가 안 된다" — 원인 발견 및 수정

## 요청 사항

"지금 supabase가 문제인지 내번호 저장으로 이어하기 로직이 안되는데 크롬 디버깅으로
확인해주고 리드미에 작성된 기능 작성도 다시한번 확인해줘"

## 원인 — Supabase 문제가 아니라, "이어하기"만 로컬 대체 수단이 없었다

`learningLog.ts`(홈/설정에 보이는 "최근 학습" 요약, 완료 개수)는 처음부터
"Supabase 요청과 별개로 이 기기 localStorage에 즉시 사본을 남기고, 다음에 불러올
땐 서버 값과 `updated_at` 기준으로 병합" 하는 방식이었다. 그런데 정작 "이어서
연습하기"가 실제로 복원하는 단어 큐 자체를 담당하는 `progress.ts`
(`saveProgress`/`loadProgress`/`listSavedProgress`/`deleteProgress`)에는 이
로컬 대체 수단이 전혀 없었다 — Supabase가 없거나(로컬 dev 환경처럼 환경변수 미설정),
일시적으로 응답이 없거나, 스키마가 어긋나 upsert가 실패하면 그냥 조용히 `null`/`[]`/
`false`만 돌려줬다.

그 결과 정확히 사용자가 겪은 증상이 만들어진다: **"학습 기록" 목록(learningLog
기반)엔 완료 개수·최근 학습 시각이 멀쩡히 보이니 "저장은 되는구나" 싶은데, 정작
"이어서 연습하기" 카드는 뜨지 않거나 눌러도 처음부터 다시 섞인다.** Supabase 자체가
문제냐는 질문엔 "그럴 수도 있지만, 설령 Supabase가 멀쩡해도 이어하기 쪽은 애초에
로컬 안전망이 없어서 네트워크가 한 번만 삐끗해도 조용히 깨지는 구조였다"가 더
정확한 답이었다.

## 수정

1. **`src/lib/progress.ts`에 `learningLog.ts`와 같은 패턴의 로컬 사본을 추가**
   (`writeLsProgress`/`readLsProgress`/`removeLsProgress`/`readAllLsProgress`,
   `word_app_progress_` 접두사). `saveProgress`는 이제 Supabase 응답을 기다리지
   않고 이 기기에 즉시 저장부터 하고, `loadProgress`/`listSavedProgress`는 서버
   값과 로컬 값을 `updated_at` 기준으로 병합해서 더 최신 쪽을 쓴다.
   `deleteProgress`도 로컬 사본을 함께 지운다. 이제 같은 기기 안에서는 Supabase
   상태와 무관하게 이어하기가 항상 동작한다(다른 기기 간 동기화만 Supabase 필요).
2. **`src/lib/supabase.ts`에 `logSupabaseError` 헬퍼 추가**, `progress.ts`·
   `mastery.ts`의 모든 Supabase 실패 지점에 연결. 지금까지는 upsert/select가
   실패해도 반환값(false/null/[])만 조용히 돌려줘서 브라우저 콘솔에 아무 단서가
   안 남았다 — 예를 들어 `progress` 테이블 기본키가 예전 스키마(`user_id, part`)로
   남아있는데 코드가 `(user_id, part, file_key)`로 upsert를 시도하면 Postgrest가
   "on conflict 대상과 일치하는 제약이 없다"는 에러를 주지만 어디에도 안 찍혔다.
   앞으로는 실패할 때마다 `[Supabase] ... 실패: ...` 형태로 콘솔에 원인이 남는다
   — 실제 배포 환경에서 F12를 열어보면 남은 원인(스키마 드리프트인지, RLS
   정책인지, 키 자체가 잘못됐는지)을 바로 알 수 있다.
3. 곁다리로 `mastery.ts`의 `computeNextMastery` 주석에 남아있던 `NOT_DUE_PUSH`
   (이미 삭제된 옛 메커니즘) 언급을 `excludeNotDue` 기준으로 정정.

로컬 `.env.local`은 Supabase 값이 비어 있어(이 개발 환경 한정) 어차피
"Supabase 미설정" 상태다 — 즉 수정 전에는 100% 재현되는 최악의 경우였다.

1. `localStorage`의 `word_app_progress_*`/`learning_log_*`를 지우고 큰 단어장
   (241개)으로 연습을 시작, 2문제만 채점한 뒤 "연습 종료하기"로 중간에 나감.
2. **수정 전**(이 세션 초반, 아직 로컬 사본이 없던 시점)에는 이 시나리오에서
   `/practice`로 돌아와도 "이어서 연습하기" 카드가 뜨지 않았을 것이다(코드상

   에러 없음.
4. `tsc --noEmit`·`eslint src/` 전체 통과.

테스트로 만졌던 `내 번호`/진행 상황 localStorage 값은 확인 후 지워서 원래
상태로 돌려놨다.

## README 재검토 — 실제로 여러 군데 낡은 설명을 발견해 고쳤다

같은 요청의 두 번째 부분("리드미에 작성된 기능 작성도 다시한번 확인해줘")으로
한글/일본어 양쪽 섹션을 코드와 대조했다. 발견한 문제:

- **`requeuePosition` 예시 코드가 완전히 옛날 버전이었다.** README엔 "남은 큐의
  절대 비율(20~40%/5~15%)"로 계산하는 예전 구현이 그대로 실려 있었는데, 실제
  `queue.ts`는 8/30~31 로그에서 이미 라운드 기반(`MIN_GAP`, 라운드 배수 구간)
  방식으로 완전히 재설계되어 있었다 — 코드 스니펫이 실제 구현과 달랐다. 정확한
  설명으로 교체.
- **"15개 라운드"가 고정값처럼 적혀 있었다.** 이번에 라운드 크기가 사용자
  조절 가능(5~50개)해졌으므로 반영.
- **이어하기의 "네트워크 끊겨도 로컬 보조 저장" 설명이 실제보다 앞서 있었다.**
  이 설명 자체는 이미 README에 있었지만, 정작 코드(`progress.ts`)에는 방금
  전까지 구현되어 있지 않았다 — 즉 README가 "이랬으면 좋겠다"는 의도를 이미
  사실처럼 적어둔 상태였다. 이번 수정으로 실제로 그 설명대로 동작하게 됐으므로
  문구를 더 정확하게(어느 테이블이 로컬 사본을 갖는지 등) 다듬었다.
- **새 기능 다수가 전혀 언급되지 않았다**: 라운드 크기 조절, 채점 버튼 크기/숨김
  설정, 애니메이션 기본값 전환, 힌트 구간별 색/크기/숨김 테마(한자 제목 강조
  포함), 홈 "오늘의 목표" 진행 링, 학습 히트맵/숙련도 분포/복습 예보, 세션
  요약 화면 — 전부 로그 파일에만 기록되고 README 본문엔 없었다. "사용성을 위해
  넣은 것들" 표와 "다른 암기 앱을 참고해 추가한 기능" 목록에 각각 추가.
- **폴더 구조 트리**의 `hooks/`가 `useUserId.ts` 하나만 적혀 있었고(실제로는
  6개), `lib/`·`components/` 목록에도 새 파일들이 빠져 있어 갱신.

한글 섹션을 기준으로 전부 고치고, 일본어 섹션도 같은 항목(코드 스니펫, 라운드
크기, 이어하기 설명, 새 기능 목록, 폴더 구조)을 동일하게 반영했다.
